# Инструкция для экзаменатора — exam-project

Документ для проверки демонстрационного экзамена (ДЭ) по разработке веб-приложения.  
Студент работает в этой папке; **README.md** в корне — краткая памятка для обучающегося.

---

## 1. Что должно быть в работе на проверку

| Ожидается | Не должно быть в сдаче |
|-----------|-------------------------|
| Только папка **`exam-project`** | Папка **`exam-guides`** (шпаргалки) — студент обязан удалить её перед сдачей |
| Файл **`server/.env`** (свои `DATABASE_URL`, `JWT_SECRET`) | Секреты в git — не критерий, но проверьте локальный запуск |
| Рабочий запуск `npm run dev` | Обязательно не «только фронт без API» |

Если рядом с `exam-project` лежит **`exam-guides`** — работа сдана не по регламенту (подсказки не удалены).

В коде могут остаться блоки **`ФАЙЛ:`** / **`БАНКЕТАМ.НЕТ:`** в комментариях — это не ошибка, но по желанию студент их убирает перед сдачей.

## 2. Быстрый запуск на машине проверяющего

**Требования:** Node.js 18+ (лучше 20 LTS), PostgreSQL 14+, служба PostgreSQL запущена.

```powershell
cd путь\к\exam-project
npm run install:all
copy server\.env.example server\.env
# Отредактировать server\.env: DATABASE_URL, при необходимости PORT и JWT_SECRET
# Создать БД в psql, например: CREATE DATABASE moy_ne_sam;
npm run db:init
npm run dev
```

| Сервис | URL |
|--------|-----|
| Сайт (Vite) | http://localhost:5173 |
| API (Express) | http://localhost:3001 |
| Health-check | http://localhost:3001/api/health |

Прокси: запросы с фронта идут на `/api` → порт из `server/.env` (по умолчанию 3001), см. `client/vite.config.js`.

## 3. Стек и структура

- **Клиент:** React 19, react-router-dom 7, Vite 6, Tailwind CSS 4  
- **Сервер:** Express 5, PostgreSQL (`pg`), JWT, bcrypt  
- **БД:** `server/db/schema.sql`, справочник `seed.sql`, админ создаётся в `server/db/init.js`

```
exam-project/
├── client/src/pages/     ← экраны п.1–5 и лендинг
├── client/src/App.jsx    ← маршруты
├── server/routes/        ← API
├── server/db/            ← схема, seed, init (логин админа)
└── server/utils/validation.js  ← правила (дубль на клиенте)
```

## 6. Чек-лист проверки по модулям

### Модуль 1 — функционал (п.1–5)

#### п.1 Регистрация (`/register`)

- [ ] Поля: логин, пароль, ФИО, телефон, email  
- [ ] Валидация на клиенте и сервере (`client/src/utils/validation.js` + `server/utils/validation.js`)  
- [ ] Телефон: `+7(XXX)-XXX-XX-XX`  
- [ ] ФИО: кириллица  
- [ ] Уникальный логин → сообщение «Логин уже занят»  
- [ ] После успеха — авторизация (JWT), переход в кабинет  

**«Банкетам.Нет»:** логин `[a-zA-Z0-9]`, мин. 6; пароль мин. 8; ссылка на логин «Еще не зарегистрированы? Регистрация».

#### п.2 Вход (`/login`)

- [ ] Вход по логину и паролю  
- [ ] `user` → `/requests`, `admin` → `/admin`  
- [ ] Ошибка при неверных данных  

#### п.3 Личный кабинет (`/requests`)

- [ ] Только для авторизованного `user`  
- [ ] Список своих заявок, статусы на русском  
- [ ] Переход на форму новой заявки  

**«Банкетам.Нет» (расширение):** слайдер в кабинете; отзывы после смены статуса админом (таблица `reviews` в БД — часто добавляется студентом).

#### п.4 Форма заявки (`/requests/form`)

- [ ] Выбор услуги из справочника (`service_types` / `seed.sql`)  
- [ ] Адрес, контактный телефон, дата/время, оплата (наличные / карта)  
- [ ] Опционально: «иная услуга» (в шаблоне есть; в «Банкетам.Нет» обычно убирают)  
- [ ] Заявка сохраняется, отображается в п.3 со статусом «Новая»  

**«Банкетам.Нет»:** 4 помещения в seed; дата в формате **ДД.ММ.ГГГГ**; без «иной услуги».

#### п.5 Админ (`/admin`)

- [ ] Только `role=admin`  
- [ ] Все заявки всех пользователей  
- [ ] Смена статусов: как минимум «в работе» / «выполнено» (ключи БД: `in_progress`, `completed`)  
- [ ] В шаблоне также `cancelled` с причиной — в «Банкетам.Нет» часто отключают  

**«Банкетам.Нет»:** подписи «Банкет назначен» / «Банкет завершен»; фильтр по статусу, сортировка, пагинация в `AdminPage.jsx` / `GET /api/admin/requests`.

### Лендинг (`/`)

- [ ] Доступен гостю и после входа  
- [ ] Слайдер, блоки услуг/преимуществ, футер  
- [ ] Название бренда в `Layout.jsx` / `LandingLayout.jsx`  

**Шаблон:** «Мой Не Сам», 3 слайда × 5 с.  
**«Банкетам.Нет»:** «Банкетам.Нет», 4 слайда × 3 с, картинки `slide-1…4` в `client/public/images/`.

### Модуль 2 — дизайн

- Макеты 390×844 (Figma) — **не обязательно** в репозитории  
- [ ] Узкая колонка на ПК (`max-w-lg` в `Layout.jsx`) — норма для мобильного макета  
- [ ] Адаптив без «сломанной» вёрстки на 390px  

Подробности: в полном комплекте гайдов — `RESPONSIVE.md` (в `exam-guides`, если студент не удалил — можно использовать при спорных случаях).

### Модуль 3 — БД и UX

- [ ] PostgreSQL, таблицы `users`, `service_types`, `requests`  
- [ ] Статусы через `CHECK` в `schema.sql`  
- [ ] Микроанимации в `client/src/index.css` (классы `animate-fade-up` и т.п.)  
- [ ] **«Банкетам.Нет»:** таблица отзывов, при необходимости убрать `cancelled` из UI/БД

## 7. API (для ручной проверки)

| Метод | Путь | Кто |
|-------|------|-----|
| POST | `/api/auth/register` | гость |
| POST | `/api/auth/login` | гость |
| GET | `/api/auth/me` | с JWT |
| GET | `/api/services` | справочник услуг |
| GET | `/api/requests/mine` | user |
| POST | `/api/requests` | user |
| GET | `/api/admin/requests?status=` | admin |
| PATCH | `/api/admin/requests/:id/status` | admin |

Токен: заголовок `Authorization: Bearer <jwt>` (см. `client/src/api.js`, `AuthContext`).

## 9. Статусы заявок

| Ключ в БД | Подпись (шаблон) | «Банкетам.Нет» |
|-----------|------------------|----------------|
| `new` | Новая | Новая |
| `in_progress` | В работе | Банкет назначен |

## 10. Типичные замечания при оценке

| Ситуация | Оценка |
|----------|--------|
| Папка `exam-guides` в сдаче | Нарушение регламента сдачи |
| Валидация только на клиенте | Сервер должен дублировать правила |
| `npm run db:init` не выполнялся | Нет таблиц / админа — п.5 не проверить |
| Несовпадение seed и констант на лендинге | Ошибка синхронизации темы |
| JWT в localStorage, но API 401 | Проверить `JWT_SECRET`, прокси, порт |
| Оставлены дефолтные `adminka` при задании «Банкетам.Нет» | Не выполнено требование задания по учётке |

## 11. Сценарий проверки за 10–15 минут

1. Запуск по §2, открыть http://localhost:5173  
2. Гость: лендинг, регистрация нового пользователя (п.1)  
3. Выход / новый браузер: вход пользователя (п.2)  
4. Создать заявку (п.4), убедиться в списке (п.3)  
5. Вход админом из `init.js` (п.5), сменить статус заявки  
6. Снова пользователь: обновлённый статус в п.3  
7. При теме «Банкетам.Нет» — отдельно: валидация логина/пароля, 4 помещения, подписи статусов, фильтры админа  
8. Узкий viewport 390px — читаемость форм
